# UART State Machine Parser & Emulator

This project was developed for **educational purposes** to practice low-level systems programming, serial communication (UART) emulation, and byte-level state machine parsing in the C programming language.

It simulates a hardware-level serial connection between a rocket and a ground station using POSIX pseudoterminals (PTY). The ground station utilizes a robust state machine to parse incoming byte streams, verify data integrity via checksums, and safely process the data using a multithreaded producer-consumer architecture.

## 🚀 Features

*   **Virtual Serial Communication:** Utilizes POSIX pseudoterminals (`posix_openpt`) to emulate a raw UART hardware connection between two separate processes.
*   **State Machine Parsing:** Implements a deterministic 4-stage state machine (`WAIT_HEAD1`, `WAIT_HEAD2`, `READ_DATA`, `CHECK_CS`) to safely extract data frames from a continuous byte stream.
*   **Data Integrity & Framing:** Custom packet framing using a 2-byte header (`0xAA`, `0xBB`) and an XOR checksum to detect and discard corrupted data (garbage data).
*   **Concurrency (POSIX Threads):** A producer-consumer model in the ground station utilizing `pthread_mutex_t` and `pthread_cond_t` alongside a ring buffer to ensure thread-safe data handling.
*   **Raw Terminal I/O:** Configures POSIX `termios` flags to disable canonical mode, echoing, and parity, ensuring pure raw byte transmission.

## 📂 File Structure

The core components of the project are:

*   **`rocket_sim.c`**: The emulator module (TX) that generates virtual telemetry data, applies framing/checksums, and opens the master pseudoterminal to transmit the byte stream.
*   **`ground_station.c`**: The receiver module (RX) that connects to the virtual serial port, reads bytes one by one, synchronizes via the state machine, and displays the validated data using concurrent threads.
*   **`serial_utils.h`**: A utility header containing the `termios` configurations required to open and set up a file descriptor for raw serial I/O.
*   **`Makefile`**: The build automation script to compile the project efficiently.

## 🛠️ Build and Run Instructions

To compile and run this project, ensure you have the `gcc` compiler and `make` utility installed (macOS or Linux environments).

**1. Compile the Project:**
Navigate to the project directory in your terminal and execute:
```bash
make
```
*This command will generate two executable binaries: `rocket_sim` and `ground_station`.*

**2. Start the Rocket Simulator (Transmitter):**
Initialize the simulated rocket, which will create the virtual serial port:
```bash
./rocket_sim
```
*Note: The terminal will output a virtual port path (e.g., `Port: /dev/ttys000` or `/dev/pts/3`). Copy this path.*

**3. Connect the Ground Station (Receiver):**
Open a **new** terminal window or split the current terminal, and launch the ground station:
```bash
./ground_station
```
When prompted with `Port (/dev/pts/X):`, paste the path generated by the `rocket_sim` in the previous step and press Enter.

## 📝 Simulation Scenario

Upon successful connection, `rocket_sim` generates simulated telemetry (timestamp, altitude, speed), packages it into a byte array starting with `0xAA` and `0xBB`, appends an XOR checksum, and writes it to the virtual serial cable. 

Concurrently, the `ground_station` reads the connection byte-by-byte. If it encounters garbage data or noise, the state machine resets and waits for the exact `0xAA` `0xBB` header sequence. Once a valid frame is identified and the checksum matches, the receiver thread signals (`pthread_cond_signal`) the consumer thread, which then safely dequeues the struct from the ring buffer and prints the synchronized altitude and speed metrics to the console.
